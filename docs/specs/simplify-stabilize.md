# 项目简洁稳定性治理

## Goal

基于简洁、稳定、常用优先的原则，分阶段优化项目结构、模块职责和验证流程，降低理解成本与维护成本，同时保持现有功能行为不回退。

## Users And Scenarios

- 项目维护者需要更快定位代码入口、职责边界和构建路径。
- 新会话中的编码代理需要更少上下文即可安全修改代码。
- 日常开发需要固定的验证步骤，减少“改完不确定是否破坏现有功能”的情况。

## Requirements

- 将治理范围限定为结构、职责和流程，不新增业务功能。
- 目录调整必须服务于可读性与职责清晰，避免仅为重构而重构。
- 重复逻辑应收敛到明确的上下文、hook 或工具函数，避免继续堆积在页面层。
- 构建、lint、桌面端打包相关的验证步骤需要形成固定执行顺序。
- 所有治理任务必须拆成可独立验证的 Trellis 子任务，一次只推进一个子任务。

## Not Included

- 新的 MQTT 业务能力。
- UI 风格改版。
- 第三方基础设施替换。
- 未经验证的大规模跨层改写。

## Acceptance Criteria

- 已形成一个治理父任务和一组边界清晰的子任务。
- 每个子任务都有明确的 `prd.md`，可直接进入后续实现阶段。
- `docs/trellis-plan.md` 已定义执行顺序、范围和验收方式。
- 第一阶段推荐从目录结构整理开始，而不是直接修改业务逻辑。

## Open Questions

- `src/app/App.jsx` 当前剩余的页面级职责边界，需要在后续子任务中结合代码现状再细化。
